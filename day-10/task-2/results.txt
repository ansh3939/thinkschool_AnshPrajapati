=== 3. BEFORE: accidental client-side filtering ===

(Note: no WHERE clause at all here - every row in the table was pulled before

=== 4. AFTER: filter pushed back into the query ===
Executed DbCommand (0ms) [Parameters=[], CommandType='Text', CommandTimeout='30']
SELECT "q"."Id", "q"."Amount", "q"."AuthorName", "q"."Category", "q"."Notes", "q"."Text"
FROM "Quotes" AS "q"

-> SQLite only returns the 3 matching rows this time.

==========================================================================
Captured from an actual `dotnet run` against the seeded quotes.db (6 rows).
`ef_compare` shows up in the WHERE clause because SQLite has no native decimal
type - EF Core's Sqlite provider stores decimal as TEXT and uses this function
to compare values correctly instead of doing a lexical string comparison.
